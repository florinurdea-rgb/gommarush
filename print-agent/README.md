# GoRush Print Agent

Prints GoRush inventory-unit labels on the warehouse printer.

```
phone / web app  →  Supabase print_jobs  →  THIS AGENT  →  Windows print queue  →  Toshiba
```

The web app **never** talks to the printer. It inserts a row into `print_jobs`
and returns immediately. This agent, running on the Windows PC that is already
connected to the printer, claims those rows and prints them.

**If this agent is offline, nothing breaks.** Jobs stay `pending` in Supabase and
print as soon as it comes back. The web app is unaffected, and no label is ever
lost.

Nothing about your existing printer setup needs to move or be reconfigured — the
agent prints through the queue that is already installed, by name.

---

## 1. Install

On the Windows PC connected to the printer:

1. Install **Node.js 18 or newer** from <https://nodejs.org> (LTS is fine).
2. Copy the `print-agent` folder onto that machine (USB stick, network share, or
   `git clone` the repo and use the subfolder).
3. Open **Command Prompt** in that folder and run:

   ```
   npm install
   ```

## 2. Configure

```
copy .env.example .env
notepad .env
```

Fill in:

| Variable | What it is |
|---|---|
| `SUPABASE_URL` | `https://sfvaqextratpnprcamwd.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase dashboard → Project Settings → API → `service_role` `secret` |
| `PRINTER_NAME` | The exact Windows printer queue name — see below |
| `PRINTER_ADAPTER` | `file` to test safely, `windows` to actually print |

The service-role key is safe here and only here: this is a trusted machine, not
a browser. It must never appear in the web app's `NEXT_PUBLIC_*` variables.

### Finding the exact printer queue name

The name must match **character for character**, including spaces. A subtly
wrong name is the most common cause of "nothing prints".

```
npm run check-printers
```

Or directly in PowerShell:

```powershell
Get-Printer | Select-Object Name, DriverName, PortName
```

Copy the `Name` column verbatim into `PRINTER_NAME`. If the name contains
spaces, that's fine — do not add quotes in the `.env` file.

You can also see it in **Settings → Bluetooth & devices → Printers & scanners**,
or **Control Panel → Devices and Printers**.

## 3. Test without printing

Leave `PRINTER_ADAPTER=file` and run:

```
npm run test-label
```

This writes `output/sample-label.pdf`. Open it and check:

- the stand letter is large and legible
- the barcode and QR are crisp
- **scan the printed barcode with your handheld scanner** — this is the
  important check, and the only way to confirm the label works before going live

Then start the agent in test mode:

```
npm start
```

Real jobs are claimed and rendered to `output/` instead of being printed. This
verifies the whole pipeline end to end without paper.

## 4. Print for real

Install a silent PDF printer. **SumatraPDF** is small, free, and the most
reliable option for this job: <https://www.sumatrapdfreader.org>

Make sure `SumatraPDF.exe` is on the `PATH`, or set the full path in
`PRINT_COMMAND`.

Then in `.env`:

```
PRINTER_ADAPTER=windows
PRINTER_NAME=Toshiba e-STUDIO 2515AC
```

If you use something other than SumatraPDF, set your own command — `{{file}}`
and `{{printer}}` are substituted:

```
PRINT_COMMAND=SumatraPDF.exe -print-to "{{printer}}" -silent -print-settings "fit" "{{file}}"
```

Start it:

```
npm start
```

## 5. Keep it running

Simplest option — a scheduled task that starts at logon:

```powershell
$action  = New-ScheduledTaskAction -Execute "npm" -Argument "start" -WorkingDirectory "C:\gorush\print-agent"
$trigger = New-ScheduledTaskTrigger -AtLogOn
Register-ScheduledTask -TaskName "GoRush Print Agent" -Action $action -Trigger $trigger -RunLevel Highest
```

Or run it as a proper service with [NSSM](https://nssm.cc).

## Label

Default 100 × 70 mm, configurable via `LABEL_WIDTH_MM` / `LABEL_HEIGHT_MM` /
`LABEL_MARGIN_MM`.

```
┌──────────────────────────────────────┐
│  GR-001            ┌──────────────┐  │
│  ROSSI GOMME       │              │  │
│  MICHELIN          │      A       │  │  ← stand letter, dominant
│  225/55 R18 98V    │              │  │
│  Obiect 2 / 4      └──────────────┘  │
│  ││││││││││││││││││││││││    ┌────┐  │  ← Code128 (handheld scanner)
│  GRU9F3A21C4B87E0D6A5FC3E11  │ QR │  │  ← QR (phone fallback)
└──────────────────────────────────────┘
```

- **Code128** carries the bare unit token, for the handheld scanner.
- **QR** carries a URL (`…/u/<token>`), so a phone camera opens the read-only
  item view.
- The token is also printed as text, so a damaged barcode can be keyed in.

The printer never invents identifiers. Every value comes from `label_data` on
the print job, generated by the GoRush system.

## Reliability

| Situation | What happens |
|---|---|
| Printer off / out of paper | Job → `failed` with the error. Retry from Admin → Coadă de printare. |
| Agent crashes mid-job | Job stays `processing`, then is auto-requeued after `STALE_JOB_MINUTES`. |
| Two agents running | `FOR UPDATE SKIP LOCKED` means each claims a different job. Never the same one. |
| Network drops | The agent logs and keeps polling. The queue is durable. |
| Same tyre scanned twice | The database allows only one open job per unit, so no duplicate label. |

## Known limitations

- **Physical printing has not been tested.** The pipeline, rendering, claiming,
  failure handling and recovery are all tested (with a mocked printer adapter,
  see `tests/print-agent-loop.test.ts` in the web app). Actual output on the
  Toshiba requires the hardware.
- A successful print command means Windows **accepted the job into the spooler**.
  Paper physically emerging cannot be confirmed from here. A job stuck in the
  Windows spooler will show as `printed` in GoRush.
- Label geometry is configured, not measured. Check `output/sample-label.pdf`
  against your actual label stock before a production run.

## Troubleshooting

**"Cannot reach Supabase"** — check `SUPABASE_URL` and
`SUPABASE_SERVICE_ROLE_KEY`. The agent verifies the connection at startup and
exits rather than failing silently on every poll.

**Nothing prints, no errors** — `PRINTER_ADAPTER` is probably still `file`. Check
the startup banner: it says `TEST MODE` when nothing will be printed.

**"'SumatraPDF.exe' is not recognized"** — not on the `PATH`. Use the full path
in `PRINT_COMMAND`, e.g. `"C:\Program Files\SumatraPDF\SumatraPDF.exe" -print-to …`

**Barcode won't scan** — increase the label width, or print at a higher DPI. The
Code128 needs roughly 0.25 mm per narrow bar to be read reliably.
